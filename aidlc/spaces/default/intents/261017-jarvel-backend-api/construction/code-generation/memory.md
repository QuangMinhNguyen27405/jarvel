## Tradeoffs
<!-- example: 2026-05-29T10:14:32Z — picked TDD over BDD this run; the team is unit-first and the domain is well-understood -->
- 2026-10-23T17:27:04Z — Repository tests run against a small in-memory table behind aws-sdk-client-mock that evaluates our condition and update expressions, rather than per-test canned responses. It costs about 150 lines of fixture but makes the concurrency (5 at once → 1 accepted) and transition tests exercise real conditional semantics, and it is reused by the API tests.
- 2026-10-23T17:27:04Z — Rearranging a day (FR5.3, FR4.3) is a bounded search: a rejected wishlist stop is tried at every position of every day and kept only where no already-accepted stop is lost. It is quadratic but tiny for ≤15 stops over ≤7 days, and it is deterministic, which keeps the fixed-rule outcome testable.
- 2026-10-23T17:39:27Z — Lambdas bundle every dependency, AWS SDK included (`externalModules: []`, ESM with a `createRequire` banner), about 0.9 MB each. That costs a little cold-start time but runs exactly the SDK versions the tests ran against instead of whatever the Node 22 runtime ships; a local synth built both bundles and the bundled ApiFn answered `/health`.
- 2026-10-23T17:39:27Z — The $25/$20 budget is created per stack, and an AWS Budget covers the whole account, so deploying staging and prod gives two identical budgets and two alert emails at $20. Accepted for now because the alarm must exist whichever stage is deployed first; one stage could skip it later.
- 2026-10-23T17:39:27Z — Both alarms fire on a single event in 5 minutes (threshold 1, missing data not breaching). With fewer than 10 invited travelers any 5xx or failed plan is worth an email, and AC6.5.3 needs one deliberately failed plan to be able to fire the alarm.
